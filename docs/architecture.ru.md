# Архитектура системы и состав публичной версии

[English](architecture.md) | **Русский**

## Полное приложение (приватный репозиторий)

Flora Sense состоит из нескольких сервисов. Клиентская часть написана на React и Vite. Она включает каталог, оформление заказов, анкету подбора букетов, страницу рекомендаций и административный интерфейс.

Nginx направляет запросы браузера к Node.js/Express API, а запросы изображений к сервису рекомендаций. Backend отвечает за пользователей, заказы, оплату, доставку и сохранение сессий подбора и обратной связи. Основная база данных работает на PostgreSQL. Для проверки принадлежности адресов зонам доставки используется PostGIS.

Сервис рекомендаций написан на Python и FastAPI. Он загружает признаки букетов из Excel, исключает варианты с нежелательными цветами, вычисляет оценки соответствия и возвращает отсортированный список.

После лайка или дизлайка клиентское приложение применяет `sessionReranking.js`. Этот модуль пересчитывает порядок ещё не показанных рекомендаций. Уже просмотренные букеты остаются на своих местах.

В полном проекте также предусмотрены подсказки адресов через DaData, тестовая интеграция YooKassa и отправка писем по SMTP. Для самостоятельной демонстрации алгоритма эти сервисы не требуются. Приложение развёртывалось как набор сервисов через Docker Compose. Конфигурация полного развёртывания в публичную версию не входит.

## Что опубликовано

В открытом репозитории находятся оригинальные функции расчёта оценок и ранжирования из `recommender/prototype/bouquet_recommender_v1.py`. Для их запуска отдельно от магазина подготовлен небольшой адаптер на FastAPI в папке `recommender/app`.

Адаптер использует **синтетический каталог из 12 букетов**. Он заменяет закрытые товарные данные и изображения, но не сам алгоритм оценки.

Также опубликованы исходный модуль сессионного переранжирования `session-reranking/sessionReranking.js`, функции расчёта метрик из офлайн-эксперимента, тесты, скриншоты и ссылка на видеодемонстрацию полного приложения.

Важно различать две части системы. Публичный endpoint `/recommend` **не применяет** сессионное переранжирование. В полном приложении Python-сервис сначала рассчитывает исходную выдачу, после чего JavaScript в браузере может изменить порядок оставшихся букетов с учётом обратной связи. В репозитории эти компоненты представлены отдельно.

## Правила ранжирования

В базовом content-based алгоритме используются следующие относительные веса признаков.

| Признак | Вес |
| --- | ---: |
| Цветовая гамма | 8.4 |
| Состав букета | 3.1 |
| Стиль | 1.8 |
| Пол получателя | 1.2 |
| Возрастная группа | 1.1 |
| Повод | 0.7 |

При оценке цветовой гаммы основной цвет получает вес 0.70, дополнительный 0.23, а совпадение общей палитры 0.07.

Цветы из `unwanted_flowers` служат жёстким ограничением. Если пользователь указал любимые цвета, применяется минимальный порог совпадения по цвету (`>= 0.25` в исходной реализации). Цветы из `favorite_flowers` дают дополнительный балл, но их наличие не обязательно.

Сессионное переранжирование учитывает исходную анкету, положительную и отрицательную обратную связь, сходство с оценёнными букетами и первоначальную позицию в выдаче. Меняется только порядок ещё не просмотренных рекомендаций. Высокая исходная оценка может перевесить влияние реакции пользователя.

## Что осталось закрытым

В публичной версии нет внутреннего каталога магазина, учётных записей и истории действий покупателей, административных маршрутов, реализации заказов и платежей, товарных изображений, резервных копий базы данных, обучающих записей, файлов моделей, конфигурации развёртывания и секретов.
